# Clan information design

The command resolves a ClanRegistry entry and asks ClanService for a TTL-cached snapshot. The snapshot contains normalized ClanInfo, raw HTML and source URL. Required `.info .name` must uniquely identify the profile; optional supplied selectors produce nullable fields. Footer `.info` is excluded through the name's nearest `.info` ancestor.

Rank width is validated within 0–100 percent and is distinct from EXP. Same-origin HTTPS image URLs are resolved against the official base. Statistics come from `.clan_section .record .clan_record > .section` only when uniquely titled Total Stat. The match field excludes its span label; graph columns are identified by win/lose labels and provide counts and displayed percentages. Missing/malformed values remain null. Season panels are excluded, and rates are not recalculated because the observed outcome counts do not sum to total matches.

LogoService hashes source URL plus HTML, deduplicates buffers, and invokes a serial, reusable Chromium renderer. Cached HTML fulfills the original navigation. Navigation waits for DOM content; readiness then explicitly requires same-origin stylesheets and all logo layers, avoiding stalled unrelated page images. The nearest ancestor containing one `.logo` is selected for an element-only screenshot with omitBackground. Blocked optional external font imports are ignored. Ambiguous marks or required asset failures yield a logged, visible logo-unavailable note. Typed failures record a safe stage and reason, including browser installation, network, styles, layers and screenshot timeouts; raw Playwright messages are not exposed. This selection and the original layered mark have been verified on the corrected public page.

`clanProfile` uses Discord Components V2 to control image order and Markdown heading sizes. A Container starts with a Media Gallery referencing the original attached `clan-logo.png`, then a level-one clan-name heading. Level-three headings introduce clan details, clan rank and overall results. A Text Display places the rank badge emoji inline before its verified website name, with Rank progress immediately underneath. `RankEmojiService.forClan` shares the member roster's cache and serialized creation queue, accepting only original official `clan_<number>.png` assets and using distinct `pb_clan_rank_<number>` names. Existing application emojis are reused across restarts, and uploads preserve original PNG bytes. Clan and member rank numbers cannot collide or be substituted for each other. Failed emoji preparation retains a link to the validated original badge; an absent or untrusted badge leaves the rank name readable. A 12-segment monospace progress bar rounds the validated percentage for its visual fill while the exact formatted percentage stays beside it. Missing/invalid progress remains N/A. Bounded escaped text stays below the combined 4,000-character component limit, with mentions disabled. A small-text footer includes the source and a Discord relative timestamp.

The command defers normally and adds `IsComponentsV2` only when editing in the completed component response. It does not mix legacy content/embeds with the component payload. Deferred clan errors also use Text Display components because a message cannot leave Components V2 after adopting that flag. Logo failure retains the profile and a visible unavailable note. Other commands retain their existing embeds. A shared request gate limits all page/API attempts and uncached browser navigation; central handling sanitizes failures and expires gracefully.
